# 제품 흐름 초안

이 문서는 자투리여행 앱의 큰 사용 흐름과 개발 단계를 정리합니다. 아직 세부 화면과 기능은 확정하지 않습니다.

## 기본 사용자 흐름

1. 사용자가 출발지와 목적지를 검색한다.
2. 검색 결과에서 출발지와 목적지를 선택해 좌표를 확정한다.
3. 현재 위치, 출발지, 목적지, 또는 대략적인 이동 경로를 기준으로 기본 경로를 잡는다.
4. 사용자가 남는 시간을 입력한다.
5. 동반자, 선호, 접근성, 날씨 민감도 같은 간단한 조건을 선택한다.
6. 앱이 기본 경로에서 크게 벗어나지 않는 자투리 스팟 후보를 계산한다.
7. 앱이 `출발지 -> 스팟 -> 목적지` 형태의 비교 가능한 경유 번들을 보여준다.
8. 사용자는 추천 이유와 예상 소요 시간을 보고 하나를 고른다.
9. 사용자는 외부 내비게이션 앱으로 경로를 전송한다.
10. 방문 후 저장, 피드백, 다음 추천 개선으로 이어질 수 있다.

## 초기 화면 구조 후보

초기 앱은 다음 정도의 구조가 적당합니다.

- 홈
  - 출발지/목적지 검색
  - 검색 결과 선택을 통한 좌표 확정
  - 남는 시간 선택
  - 빠른 조건 선택
- 추천 결과
  - 추천 번들 카드 목록
  - 예상 추가 시간, 추천 이유, 접근성 요약
- 스팟 상세
  - 사진, 설명, 운영 정보, 주차/접근성, 체류 시간
  - 내비게이션 열기
- 저장한 장소
  - 나중에 볼 자투리 스팟
- 설정
  - 기본 동반자 유형, 접근성 선호, 데이터 출처 안내

## MVP 범위

MVP는 “정교한 지도/실시간 내비게이션 앱”이 아니라 “경로와 시간 조건을 반영한 관광 추천 앱”으로 잡습니다.

현재 프로토타입은 이 MVP 범위를 Mock 데이터 기반으로 구현합니다. 실제 TourAPI/Kakao 연동 전에도 사용자는 홈에서 출발지와 목적지, 조건을 고르고, 추천 카드 목록을 보고, 상세 화면에서 장소를 저장하거나 외부 경유 경로로 이동할 수 있습니다.

MVP에 포함할 것:

- 강원 지역 중심의 기본 앱 구조
- 출발지와 목적지 검색 및 좌표 확정
- 남는 시간 선택
- 동반자/접근성/날씨 민감도 같은 간단 필터
- 기본 경로와 경유 경로를 비교하는 추천 카드 UI
- 추천 이유 표시
- 외부 내비게이션 앱 열기
- TourAPI 연동 또는 TourAPI 형태를 닮은 시드 데이터
- TourAPI 키워드 검색 기반 관광 목적지 검색
- VWorld 등 무료 공공 지오코딩 기반 주소 검색 준비
- Kakao Mobility 길찾기 API 구조를 닮은 경로 모델
- 타입 안정적인 데이터 모델

MVP에서 미룰 것:

- 자체 내비게이션
- 앱 내부 자체 실시간 교통 최적화
- 복잡한 개인화 추천
- 운영자 관리 페이지
- 지역기관 데이터 관리 워크플로우
- 전체 강원 관광지 완전 수집
- 로그인 기반 소셜 기능

## 개발 단계

### 1단계: 앱 골격

- 화면 구조 결정
- 라우팅 방식 결정
- 기본 디자인 토큰 정리
- 추천 카드 UI 만들기
- Mock 데이터로 흐름 확인

### 2단계: 데이터 모델

- 관광 스팟 타입 정의
- 추천 조건 타입 정의
- 추천 결과 타입 정의
- TourAPI 응답을 앱 내부 모델로 변환하는 계층 설계

### 3단계: 추천 프로토타입

- 남은 시간 기준 필터
- 경로 이탈 부담 기준 필터
- 카테고리별 추천 번들 구성
- 추천 이유 생성
- 날씨/접근성 조건은 우선 간단 가중치로 처리

### 4단계: 지도와 위치

- 현재 위치 권한 처리
- 목적지/경로 입력 방식 결정
- 지도 SDK 또는 외부 지도 앱 연계 방식 검토
- 외부 내비게이션 앱 열기

### 5단계: 공공 데이터 연동

- TourAPI 키 관리
- 관광지 기본 정보 수집
- 이미지/주소/좌표/분류/운영 정보 정규화
- 무장애 정보와 연관 관광지 정보 결합

### 6단계: 개발 빌드와 실기기 테스트

- Expo Go에서 빠른 확인
- Expo Dev Client로 네이티브 기능 확인
- Android 개발 빌드
- iOS 개발 빌드 또는 Mac/Xcode 환경 확인

## 추천 로직 초안

추천 점수는 처음부터 복잡하게 만들지 않습니다. 초기는 설명 가능한 규칙 기반으로 시작합니다.

현재 구현된 추천 결과는 단일 장소가 아니라 하나의 경유 경로 번들입니다.

```text
기본 경로: 출발지 -> 목적지
추천 번들: 출발지 -> 스팟 -> 목적지
```

후보 점수 요소:

- 기본 경로선과 후보 스팟 사이의 거리
- 기본 경로 대비 예상 추가 운전 시간
- 사용자가 입력한 남는 시간과의 적합도
- 체류 예상 시간
- 카테고리 선호
- 날씨 영향
- 주차 가능성
- 접근성 정보
- 공식 데이터 출처 신뢰도
- 강원 지역 특화 우선순위

추천 결과는 점수만 보여주지 않고, 사람이 이해할 수 있는 추천 이유로 풀어야 합니다.

예시:

- 현재 경로에서 크게 벗어나지 않습니다.
- 40분 안에 짧게 다녀오기 좋습니다.
- 주차와 보행 부담이 낮습니다.
- 비 오는 날에도 이용하기 비교적 좋습니다.
- 강원 공식 드라이브 코스와 가까운 지점입니다.

## 산출물 관점

이 프로젝트는 공모전 산출물 성격을 갖습니다. 따라서 단순히 앱이 동작하는 것뿐 아니라 “왜 이 서비스가 필요한지”와 “어떤 공공 데이터를 어떻게 활용했는지”가 앱 안팎에서 드러나야 합니다.

중요 산출물:

- 실제 동작하는 앱
- 서비스 소개와 사용자 시나리오
- 데이터 활용 구조 설명
- 추천 로직 설명
- 화면 흐름 또는 데모 영상
- 공공 데이터 출처 정리
- 향후 발전 방향
